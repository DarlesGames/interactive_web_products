## Особый контекст: существующий проект
- В **старом** плане запросы 1–4 уже выполнены. Номер **следующего** запроса — 5 (новый план миграции); НЕ запускай автоматически старый запрос 5.
- Текущий исходный код **не предоставлен в пакете**. При первом запросе аудируй текущий репозиторий: что уже есть, как запустить и какие тесты. Не утверждай, что конкретные файлы уже существуют; не удаляй существующие данные до проверки.
- Минимизируй переработку: переиспользуй рабочие HTML/CSS, адаптивную вёрстку, текстовый/голосовой ввод и механизмы запуска. **Удаляй старые сценарии знакомств только после переноса или отключения устаревших экранов и проверки нового потока**.
- Не переписывай проект с нуля, не меняй стек и не устанавливай зависимости без технического основания и разрешения.

## Новый продукт
- **Название:** «Очень странные дела». Формат: браузерная детективная игра для обучения русскому как иностранному, уровень A2.
- **Главный цикл:** прочитать загадку → выбрать свидетеля → задать свободный вопрос голосом/текстом → получить короткий ответ на основе известных ему фактов → собрать улики → «Моя версия» → проверка 4 элементов → итог.
- **Первая история:** «Сообщение из пустой комнаты», коворкинг «Пятый этаж», пять свидетелей: Аня, Максим, Лена, Илья, София.
- Нельзя подменять свободный вопрос заранее подготовленными кнопками-ответами; готовые кнопки допустимы только для служебных действий.

## Архитектурные запреты
- Без backend, БД, регистрации, платной LLM/API, универсальной платформы и админки в MVP. Используй текущий стек HTML/CSS/JS, без сборки если проект уже так устроен.
- UI не определяет истинность фактов. Детективный движок и контент независимы от DOM.
- Единственный источник фактов — данные истории. Не генерируй фактов на основании внешнего ИИ или случайной реплики.
- Сопоставляй субъект + действие + объект + отрицание, а не только ключевое слово. При сомнении — `UNKNOWN`, никогда случайное YES/NO.
- `YES`, `NO`, `IRRELEVANT`, `UNKNOWN` — логические коды. Если персонаж не знает факт или скрывает его, показывай специальную безопасную реплику, **не изображая достоверное отрицание**.
- Секреты не показывать интерфейсом до раскрытия. Учти: в полностью статическом приложении JSON истории с разгадкой может прочитать технически подготовленный пользователь через DevTools. Это **демонстрационная**, а не криптографическая защита.
- Ответ короткий, от первого лица, простой русский А2. Если есть отрицание в вопросе, формируй недвусмысленный ответ полным предложением.
- Нельзя выдавать автоматическую точную оценку русской грамматики/произношения без соответствующего механизма.
- Голос через Web Speech API с `ru-RU` как доступная возможность, **текстовый ввод всегда доступен**, распознанный текст можно исправить.
- Не подключай внешние фото по URL из исходных документов и не используй фотографии без прав.

## Правила работы
1. Делай **только** пункт текущего запроса; никаких самовольных следующих этапов.
2. Вначале опиши обнаруженные файлы и минимальный план изменений (для самого первого запроса — только аудит).
3. Сохраняй работоспособную версию; после каждого изменения проверь доступные тесты и основные сценарии.
4. Не подставляй свои объяснения в сюжетные пробелы: `docs/08_OPEN_ISSUES.md` описывает неподтверждённое.
5. Отчёт: «изменено / проверено / ограничения / следующий запрос»; не говори, что проверил микрофон физически без реального теста.
