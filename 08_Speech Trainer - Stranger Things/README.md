# Очень странные дела — спецификация для Codex

**Текущий статус:** проект в разработке. Редакция 2 дела №001: 21 факт, раскрытие по собранным уликам, разные реакции свидетелей и полностью проходимая цепочка расследования. Авторское расширение истории выполнено по запросу пользователя. По запросу пользователя архив прежнего приложения `old/` удалён; рабочая версия находится в корне проекта.

## Запуск реализованной версии

Нужен Node.js; установка пакетов и сборка не требуются:

```powershell
node tools/serve.mjs
```

Открыть **http://127.0.0.1:8080**. Если этот адрес уже обслуживает текущую папку, используйте запущенный сервер. Переоткрытие страницы сбрасывает состояние; долговременного сохранения нет. Для остановки сервера — Ctrl+C в его терминале.

Продукт включён в общий репозиторий демонстраций Darles Games. [Открыть опубликованный речевой тренажёр](https://darlesgames.github.io/interactive_web_products/08_Speech%20Trainer%20-%20Stranger%20Things/).

При запуске из корня общего репозитория используйте `py -m http.server 8080` и откройте `http://localhost:8080/08_Speech%20Trainer%20-%20Stranger%20Things/`. Имя папки сохраняется без изменений; пробелы в URL кодируются как `%20`. GitHub Pages публикует продукт из `main`, `/ (root)`; сборка и серверная часть не нужны.

```powershell
node --test --test-isolation=none tests/*.test.mjs
```

Ранее сохранённые отчёты в `docs/09–16` описывают историю разработки, поэтому упоминания архива и 122 архивных тестов в них относятся к прошлым этапам.

Подробности аудита до правок: [отчёт миграции](docs/09_IMPLEMENTATION_REPORT.md). Результаты первоначального тест-плана, исправления сопоставления и проверки голоса: [отчёт проверки качества](docs/10_QUALITY_REPORT.md).

Этапы диалога: [естественные вопросы](docs/11_CONVERSATION_REPORT.md), [встроенный сценарный чат-бот и текущие проверки](docs/12_CHATBOT_IMPLEMENTATION.md). Вопрос об отсутствующем факте отделён от непонятной фразы; распознанное действие само по себе не разрешает ответ YES/NO.

Последнее улучшение: [визуальное оформление по референсу и портреты](docs/16_VISUAL_DESIGN.md); [ассеты и промпт фона](assets/ASSETS.md). Предыдущие этапы: [речевая опора для РКИ](docs/15_RKI_CONVERSATION_SUPPORT.md), [расследование с постепенным раскрытием](docs/14_STORY_AND_DIALOGUE.md), [выход из непонятных вопросов](docs/13_GUIDANCE_AND_LANGUAGE.md).

В чате есть панель **«Помощь с вопросом»**: 20 речевых задач, короткие пояснения, начало фразы, сборка из частей и пример по запросу. Любая вставка попадает в редактируемый черновик; отправка ручная. Свой текст можно ввести или произнести без помощи. Выполненные задачи уходят из списка; следующие учитывают свидетеля и собранные сведения. Если у свидетеля нет новых доступных тем, панель помогает выбрать другого. Обучение модели, API и установка пакетов не нужны.

**Расположение чата:** поле ввода идёт сразу после переписки. Речевая помощь вынесена в отдельную правую колонку на экранах шире 860 px. На телефоне и узком планшете она находится ниже чата, изначально свёрнута и доступна по кнопке «Помощь» в шапке разговора. Раскрытие помощи не меняет положение ввода. Основной текст реплик и ввода — 17 px, учебные пояснения и служебный текст — от 14 px. На экранах до 360 px кнопка отправки находится под полем. На телефоне открытие свидетеля не вызывает автоматического фокуса на вводе.

**Компактный режим ПК:** при ширине от 861 px экраны помещаются в окно без прокрутки страницы. Внутри чата — обычная вертикальная прокрутка полной переписки; после отправки виден последний ответ. Речевая помощь разделена на вкладки «Задача», «Собрать», «Пример», «Фразы». Материалы открываются в отдельном постраничном окне; автоматическая подсказка не прерывает разговор этим окном. Ввод остаётся непосредственно под диалогом. На мобильном сохраняются обычная прокрутка и полная лента переписки.

Последняя проверка: 288 тестов — PASS; пять браузерных сценариев (`check-ui`, `check-chatbot-ui`, `check-investigation-ui`, `check-layout-ui`, `check-compact-ui`) — PASS. Расположение проверено на ширинах 320–1280 px; компактные экраны — на 1280×640, 1280×720, 1366×768, 1440×900, 1024×768 и 1920×1080, включая экран правильного результата. Проверены все разделы помощи, прокрутка истории, доступность всех слов длинного вопроса и постраничные материалы. Пример «Кто был в тот вечер?» проверен и в интерфейсе. Реальная экранная клавиатура и физический микрофон в автоматизации не использовались.

## Реализованный поток

Главная → завязка дела → карточки пяти свидетелей → расследование с общей статистикой → «Моя версия» → результат после совпадения четырёх частей. Старые сценарии и оценка знакомства не импортируются активным приложением. Стили, форма и голосовой адаптер переиспользованы из архива.

В расследование встроен локальный сценарный чат-бот. Можно спросить «Что вы знаете о компьютере?», продолжить «Что ещё?», уточнить неполный вопрос («Вы отправили?» → «Сообщение»), спросить «Когда?» после ответа с известным временем. «Помоги» показывает темы конкретного свидетеля; приветствия и служебные реплики не увеличивают счётчик. Бот не требует сервера, ключа или загрузки модели. После загрузки дела текстовый диалог работает без сети.

Источник истории — `data/cases/case-001.json`; роли и публичные описания сверены с `docs/04_CASE_001.md`. `knownBy` проверяется для каждого ответа по факту. Истинность и осведомлённость по десяти исходным фактам не менялись. В JSON добавлены короткие ответы, публичные карточки, словари, темы и канонические публичные высказывания свидетелей с указанием источника и доступа. «Я говорил, что ушёл в 21:30» остаётся заявлением Максима и не превращается в доказанную улику.

Счётчик учитывает уникальные смысловые вопросы к конкретному свидетелю; повторный request ID не обрабатывается. Перефразирование одного утверждения не увеличивает счётчик, хотя видимо в протоколе. Непонятный уникальный вопрос считается принятым, но не понятым. «Повтори» — служебное действие без нового факта. Подсказки открываются на 3/6/9, ручная кнопка берёт следующую ещё не показанную. Смена свидетеля сохраняет протокол и его черновик, но очищает местоименный контекст.

Продолжение темы выбирает ещё не записанный доступный факт; при исчерпании сведений бот сообщает об этом. Уточнение хранится только в разговоре с текущим свидетелем. Приветствие или помощь сохраняют ожидаемое уточнение; новый полный вопрос заменяет его. Заявления из публичных карточек не увеличивают число ответов по подтверждённым фактам.

После непонятного вопроса бот предлагает конкретную доступную тему. «Да», «давай», «расскажи» продолжают именно последнее предложение; отказ переключает тему. При повторном затруднении появляется пример вопроса. Опечатки в названиях тем сначала требуют подтверждения. Когда сведения исчерпаны, бот предлагает список свидетелей или экран версии и переходит туда только после согласия. Подсказки к разговору отделены от фактических ответов и не попадают в улики.

Голос работает по нажатию в вопросах и версиях: итоговый текст редактируется и отправляется вручную; предварительный не обрабатывается. При отсутствии API, отказе микрофона или ошибке сети остаётся текстовый режим. Реальный микрофон в автоматических тестах не использовался.

Локальный словарь учитывает роли участников, род местоимений, несколько проверенных ошибок А2 и запись времени `21 30`. Проверка версии требует связей между исполнителем, действием и объектом; перестановка слов не меняет исполнителя, распознанные противоречия отменяют совпадение. Это ограниченные правила дела №001: неподдержанная фраза может потребовать переформулировки.

**Расширение контента:** в редакции 2 явно заданы знания о ключе, родстве, ноутбуке и программе, а также условия раскрытия. Сквозной тест получает все четыре части разгадки через разговоры. Можно спросить «Что мы знаем?», «Почему?», «Что было дальше?», выразить недоверие или поддержку. Короткие продолжения используют контекст только текущего свидетеля. Модуль `questionMeaning.js` расширяет разбор переформулировками: вежливые вводные, словоформы, синонимы, перестановка слов и открытые вопросы о присутствовавших тем вечером. Все значимые слова должны соответствовать разрешённому вопросу; падежи имён, новые условия и отрицания нельзя просто отбросить. Ответ по-прежнему проходит `knownBy` и условия раскрытия. Это локальные правила дела, не универсальное понимание русского: неизвестные варианты требуют уточнения. Несущественных фактов нет: `IRRELEVANT` проверен на искусственной конфигурации. JSON остаётся доступен через DevTools; защиты от просмотра исходников нет.

## Суть
Образовательная браузерная детективная игра уровня А2 по русскому как иностранному. Игрок расследует происшествие и сам формулирует вопросы пятерым свидетелям. Каждый отвечает только на основании своей осведомлённости. Игрок выдвигает версию, а движок проверяет четыре обязательные части разгадки.

**Дело №001:** «Сообщение из пустой комнаты» в коворкинге «Пятый этаж»; подозрительное сообщение в 22:17, запертая комната №5, мокрые следы, фото, окно, старый компьютер и ноутбук.

## Где начинать
1. Положить содержимое этого пакета **в корень существующего репозитория VS Code** (сначала сохранить копию прежних документов; проверить конфликт `AGENTS.md`).
2. Открыть `docs/00_MIGRATION.md` и `docs/CODEX_NEXT.md`.
3. Передать Codex **новый запрос №5: аудит**. Никаких массовых изменений до его ответа.
4. Дальше запросы №6, №7 и т.д. выполнять последовательно после ручной проверки.

## Базовые ограничения
Один завершённый детектив, минимум пять свидетелей, локальный JS-движок, голосовая попытка + надёжный текстовый обход, без API-ключей и сервера. Публикация статического приложения на GitHub Pages при сохранении относительных путей. Критерий готовности: корректность ответов, а не их разнообразие.

## Важно о загаданном сюжете
Исходная история содержит недосказанности и несколько потенциальных несогласованностей. Не «чинить» их выдумками. См. `docs/08_OPEN_ISSUES.md`. Стартовый JSON — **каркас для заполнения**, а не полный корпус подтверждённых ответов для каждого персонажа.
