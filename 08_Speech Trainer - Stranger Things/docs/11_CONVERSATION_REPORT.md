# Естественные вопросы и сценарный чат-бот

## Обнаруженная проблема

Вопрос пользователя Максиму: «Когда вы уходили вы выключили компьютер?» возвращал «Я не понимаю вопрос». Причины разные:

1. Существующий `parseQuestion.js` сопоставлял только утверждённые отношения с десятью фактами. Не поддерживал действие «выключить» и придаточное «когда вы уходили».
2. Самого факта о выключении компьютера Максимом в истории нет. Нельзя выводить его из факта автоматического включения или из времени ухода. Поэтому даже хороший распознаватель не может достоверно выбрать «да» или «нет».

## Изменено

В существующем HTML/CSS/JS приложении сохранены UI, голос, данные и запуск. Без зависимостей и внешних API.

- В `normalize.js` добавлены формы множественного числа/вежливого обращения и отдельные действия «выключить/отключить», «уйти». Они не смешаны с автоматическим включением компьютера.
- Новый чистый модуль `parseRelation.js` распознаёт ограниченные отношения субъект–действие–объект и контекст ухода. Поддерживает проверенные перестановки слов, формы с «ли», время перед уходом и после главного вопроса, вежливые вводные слова. Отрицание и непонятные дополнительные условия не удаляются.
- `parseQuestion.js` сначала ищет точный факт прежним безопасным способом. Если совпадения нет, отдельный слой может распознать отношение с `confidence='medium'`, `factId=null`. Этот результат никогда не разрешает фактический YES/NO.
- `storyEngine.js` отделяет такой случай внутренним кодом `NO_FACT`, сохраняя пользовательский статус UNKNOWN. На исходный вопрос Максим отвечает: «Я не могу сказать, выключал ли я компьютер». Это безопасная незаданность ответа, а не добавленный факт «он выключил» или «он не выключил».
- «Скажите, пожалуйста, вы отправляли сообщение?» теперь использует существующий факт и авторский ответ. Условие «когда вы уходили» не отбрасывается ради уверенного ответа на другой, безусловный вопрос.
- Нет новых улик, баллов понимания или записей в `discoveredFacts` при `NO_FACT`. Секреты не используются для составления таких ответов.

## Что предлагается для полноценного диалога

Это первый шаг, а не обещание понимания произвольного русского текста. Бесконечное добавление отдельных фраз не устранит недостаток знаний персонажей.

Для текущего продукта предлагается сценарный чат-бот, который полностью работает в браузере:

1. Согласовать подробную таблицу знаний пяти свидетелей: время, действия, компьютеры, доступ в помещения, наблюдения; для каждой записи — точная формулировка, истинность, `knownBy`, при необходимости явное условие раскрытия. Набор тем не должен подменять свободный ввод готовыми ответами.
2. Разбирать общие конструкции вопросов отдельно от фактов: кто сделал, что сделал, когда/где, отрицание, вежливое обращение, придаточные. Неизвестное время или условие не стирать.
3. Различать «вопрос понятен, сведения не заданы», «свидетель не знает», «нужно уточнить объект/действие». Уточнение должно помогать продолжить разговор, не подсказывая секрет.
4. Каждую реальную непонятую фразу добавлять в корпус приёмки вместе с ожидаемым смыслом, а не только с желательным красивым ответом.

Это развитие существующих локальных модулей, а не замена проекта. Конкретный ответ Максима о выключении, новые сюжетные детали и полная матрица знаний требуют авторского решения. Они не добавлены в этой задаче.

GitHub Pages публикует статические HTML/CSS/JS, поэтому такая архитектура совместима с ним: [официальное описание GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages). Локальный `tools/serve.mjs` нужен только для разработки. Репозиторий и публикация не создавались. Сетевая языковая модель — отдельный архитектурный вариант с внешним сервисом; в текущие ограничения она не входит и здесь не подключалась.

Следующий запрос: согласовать недостающие факты и затем расширять покрытие конструкций на их основе. Рабочая локальная версия оставлена на **http://127.0.0.1:8080**.
