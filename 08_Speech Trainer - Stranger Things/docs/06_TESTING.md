# Приёмка и стратегия тестирования

## Обязательные 30+ вопросов для дела
По исходной концепции — минимум 30 тестовых реплик: по 5 истинных, ложных, несущественных, перефразированных, с грамматическими ошибками, непонятных/нерелевантных. **Если источник не содержит 5 подтверждённых фактов класса — сначала дополнить сценарий с согласованием, а не выдумывать ответы только ради тестов**. Для тестов `IRRELEVANT` нужен явно подтверждённый несущественный факт с известным свидетелем; исходная таблица почти не даёт таких фактов.

## Автоматические тесты движка
- Уверенное YES на знании подтверждённого факта: Аня → «София была в здании после девяти тридцати?» → подтверждение присутствия.
- Уверенное NO: Максим → «Ты отправил сообщение?» → «Нет, я его не отправлял».
- Не путать субъекта: «Максим отправил?» и «София отправила?» — разные вопросы; второй не должен отрицаться на основании факта о Максиме.
- Не путать действие: «Максим отправил сообщение?» vs «Максим видел сообщение?» — второй нельзя отвечать первым фактом.
- Свидетель не знает: Лена → «София искала старый ноутбук?» → не «да» и не «нет», а «Я этого не знаю».
- `knownBy=[]` (призрак оставил следы) → никто не отвечает уверенным YES/NO только на основании глобальной истинности.
- Неопределённый `его` без контекста → уточнение.
- Неизвестный вопрос → UNKNOWN; не приписывать IRRELEVANT без факта.
- Отрицание: «Ты не отправлял сообщение?» → естественный ответ «Нет, я его не отправлял», без двусмысленного голого «Да».
- Переключение героя: `ты` пересчитывается; старые знания не переносятся.
- Непустой вопрос учитывается один раз даже при двух событиях Web Speech API.
- 3, 6, 9 → каждая подсказка ровно один раз; ручная подсказка не повторяется при автопороге.
- Четыре составных пункта решения = CORRECT; один/три = PARTIAL; бессмысленный набор слов не должен стать CORRECT.
- Спойлер-данные не видны в интерфейсе/логе/ошибках до финала.

## Ручная проверка
`tests/case-001-manual.md` содержит проверочные фразы и ожидаемые правила. Результаты тестов следует фиксировать PASS/FAIL/TODO; не объявлять всё протестированным, если не запускалось.

## Приёмка продукта
- Первый экран и правила; выбрать дело №001; открыть 5 свидетелей.
- Можно самостоятельно формулировать вопросы, задавать их письменно/голосом при доступности SpeechRecognition, исправлять распознанное.
- Свидетели различаются и не говорят за других.
- Ни разу не получить уверенного неверного утверждения при отсутствии знания или неоднозначности.
- Ответы по-русски от первого лица, короткие, А2.
- Подсказки по порогам и кнопке.
- Частичная и полная версии корректно различаются.
- В конце разгадка + статистика.
- На браузере без микрофона приложение полностью работает с клавиатурой.
- GitHub Pages правильно загружает JSON/JS с относительными путями.

## Критичный регрессионный тест
Разные говорящие могут иметь разные знания **об одном и том же факте**. Принятие верного факта из глобального JSON без проверки `knownBy` — баг блокирующего уровня.
